# Verification

How the plug-ins are tested for correctness and bit-exactness. Part of the [documentation index](../README.md#documentation).


### Method

- **Reference:** the unchanged upstream core (`tools/exact/core_orig`) and recorded **golden values** (`tests/golden.json`): hashes and CPU times for the core of v1.21 and mk2, for the three plug-ins on the plug-in level, and for the prepared SC-88 Pro ROM set. They are generated with `tools/make_golden.sh` and renewed after every deliberate change of the sound.
- **Test material:** the polyphony test `SC55-Polyphony-Test.mid` (generated by `tools/midi/gen.py`), game music (E1M1, Animus, Duke Nukem 3D "grabbag"), and LCD test files (StarGame, 3X3EYES).
- **Environment:** the automated tests ran under Wine on Linux. The author confirmed playback on Windows (CPU measurements above, glitch-free playback of the "grabbag" song with both SC-55 variants, running back to a single unit); the SC-88 Pro and its map switch run on the author's machine. Wider testing in different DAWs is still open.

### XG mode (SC-8820)

`tools/test/xg_translate_test.cpp` checks the translator alone (`g++ -std=c++20 -I src/src tools/test/xg_translate_test.cpp`; no ROMs): held-back Bank Select, drum kit mapping, part switching to a drum part and back, Drum Part Protect, Master Volume, dropping of other XG SysEx, port B, and the end of XG mode by GM / GM2 / GS resets. End to end, the Linux SC-8820 plug-in rendered 4.5 s of an XG file (XG System On, bank 0 / LSB 16 / program 24, drum bank 127 Room on channel 10, a second drum part on channel 11) and the same song written by hand in GS form (GS Reset, CC 0 = 0, CC 32 = 4, program change, `40 1A 15 02`): the two renders are **bit-identical**, also when XG mode is turned on from the SETUP menu instead of by XG System On, and the XG file without XG mode sounds different (CC 32 = 16 is not a map). The unit test also covers the effect messages (reverb / chorus type and return, defaults after XG System On, part sends, dropped CC 94, the insertion effect: type, settings, EQ parameters, EFX sends following CC 91, part switch on and off); the twin test needs the XG default effects in the GS version too (`40 01 30` = 4, `34` = 48, `33` = 96, `38` = 0). Ten XG songs were rendered completely and compared with S-MU2000 recordings: level envelopes correlate 0.96-1.00, the mean band spectrum error is 3.3 dB (3.4 dB before the reverb calibration; Galactic Invasion 3.0 -> 2.1 dB). Raising the reverb level further did not help. **Voice table:** the SC-8820 variations that exist were found from a render of all 128 x 128 Bank Select MSB x program combinations (a variation that does not exist leaves the previous sound, as the GS manual says; the result matches the instrument list of the SC-8820 manual). As a check of the comparison, the XG basic voices (LSB 0) find SC-8820 variation 0 in 41 % of the programs (chance: 7 %); a perfect match is not expected because the two units have different samples. The table only lists voices whose best SC-8820 variation is closer than the basic voice by a margin of 3. Measured over the ten songs as the timbre distance per 0.19 s frame (24 bands, level removed, louder 70 % of the frames): 5.07 dB without the table, 4.79 dB with it; seven songs come closer (Slunky 7.77 -> 6.40, Coolie 4.70 -> 4.13, Galactic Invasion 6.47 -> 5.97), three stay the same, none gets worse. A looser table (2433 voices, margin 1) made two songs worse and was dropped. Six more S-MU2000 song recordings (XGISGOD, Cajun Down Home, Matrix, Stars, Foot Prints, Squiggles) served as an independent check of the table: 5.06 dB without it, 4.88 dB with it (XGISGOD 8.10 -> 7.02, Stars 3.68 -> 3.64, the others within 0.01). The most used voices below the margin in all 16 songs were then tried one by one in the song that uses them (26 renders): eight made their song come closer and were added (LSB 32 / program 4 to variation 8, 43/24 to 24, 24/48 to 4, 66/18 to 8, 33/5 to 8, 32/35 to 8, 40/19 to 16, 40/4 to 10), six made it worse and stay at the basic voice. With them: 4.71 dB over the first ten songs (Love You 4.91 -> 4.47, Coolie 4.13 -> 4.00), 4.62 dB over the six (Foot Prints 5.09 -> 4.06, XGISGOD 7.02 -> 6.59); no song gets worse. Each added voice was chosen with the song that tests it, so this part is not an independent check. An XG file with LSB 34 / program 6 and its GS twin with CC 0 = 10 render bit-identically. The reverb / chorus calibration and the finding that CC 94 is silent on the S-MU2000 come from `testmidi/xg_effect_cal` (`make_xg_extra.py` generates it). **Insertion effect:** an S-MU2000 recording of `testmidi/xg_insertion_cal` (`make_xg_insertion.py`: 11 variation types as insertion effect on clean guitar, overdriven guitar, electric piano and strings, plus parameter sweeps) was compared with SC-8820 renders of 28 GS EFX types and parameter grids, by the change each effect makes to the dry voice (band spectrum with the level removed, modulation, decay after the note). Rendered through the translator, the calibration file comes closer to the recording than without the insertion effect for Distortion / Overdrive / Amp Simulator (17.4 -> 7.2, 16.6 -> 5.8, 20.2 -> 10.4; 22 of 24 slots), the delays (14-15 -> 10; 10 of 12 slots), the 3-Band EQ (10.4 -> 9.3; 9 of 10 slots) and Auto Wah (12.8 -> 12.2; 6 of 10 slots). The GS Stereo-EQ needs its M2 gain set flat (its default cuts the mid range); its M1 frequency was measured as 1320 Hz x 2^((value - 64) / 26). Of the ten songs, only Energy Rider uses an insertion effect (Distortion): 3.93 -> 3.82 dB; the other nine render bit-identically. In the 134-song archive 16 songs use the variation block as insertion effect (3-Band EQ 9, Auto Wah 4, Distortion, Phaser and Delay L,C,R 1 each). Only the translation is covered; whether the chosen sounds are the right ones for XG files needs listening.

### Polyphony test

Nine rounds with 20 / 40 / 64 / 96 / 128 / 160 / 200 / 240 / 300 organ notes (one partial per note). The test tone is the **oldest** note; if it is still audible, nothing was stolen. Voice Reserve is set to 0 by SysEx (`F0 41 10 42 12 40 01 10` + 16 x `00` + `2F F7`), otherwise the firmware protects a test tone on its own channel and the test shows nothing.

| Configuration | Test tone audible until | Silent from |
| --- | --- | --- |
| Original 24 / 28 | round 1 | round 2 |
| Poly 128 (144) | round 5 | round 6 |
| Poly 256 (264 / 280) | round 8 | round 9 |

Awake instances per round (v1.21, dynamic): 1 / 2 / 3 / 5 / 6 / 7 / 9 / 11 / 11. SC-88 Pro: audible until round 8, round 9 silent, units 1 -> 4, every wake-up 0.4-0.6 ms without replay, units go to sleep after every round.

### Bit-exactness

- E1M1 on v1.00 / v1.21 / v2.00 and the polyphony test on v1.21 / MkII: identical to the original core (`tools/exact/verify.sh`, 5 combinations).
- The timer optimisation, the memory changes (shared wave ROM, LCD buffer), the state copy, the volume stage at 1.0 and the incremental LCD are checked against `tests/golden.json`: identical.
- With 24 / 28 voices or fewer, plug-in output equals a single module (hash).
- The SC-55 code with the SC-88 Pro engine added is byte-identical to the version before it.
- SC-88 Pro: three runs with embedded ROMs equal the golden value; the voice counter and the map switch were tested separately.

### Other checks

- **Windows (Wine):** CTF test (bank 1, program 17): RMS 0.0432 (v1.21), 0.0301 (MkII), about 0.0109 (SC-88 Pro); VST2 and CLAP load, editor opens, state is saved and loaded, host change notification arrives.
- **Languages:** menu language checked with `de_DE`, `en_US`, `fr_FR` (French gives English).
- **LCD:** SysEx text and bitmap animation (StarGame 0.13 s; 3X3EYES text + bitmaps) on SC-55 v1.21 and SC-88 Pro; key shift test +6 / -12 matches plug-in data and firmware LCD.
- **Builder:** nested folders, arbitrary file names, foreign files, original `rom2` only (CTF applied), one set only (only that plug-in), MkII from CTF `rom2` byte-identical to MkII from the patched original, junction / symlink folders.
